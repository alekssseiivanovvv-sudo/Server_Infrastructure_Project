# Python Web Backend

## Overview

The backend is a small Flask application served by gunicorn inside the `python-backend` container. It implements the shop API, stores data in PostgreSQL and product images in the Garage S3 cluster.

| Item | Value |
|---|---|
| Language | Python 3.12 |
| Framework | Flask 3.0.0 |
| Server | gunicorn 21.2.0 (2 workers, 60 s timeout) |
| Database driver | psycopg2-binary |
| S3 client | boto3 (path-style, Signature v4) |
| Port | `5000` (internal only) |

The backend never talks to a database or storage node directly. It uses the local HAProxy node, which routes PostgreSQL traffic (port `5000`) to the current Patroni primary and S3 traffic (port `3900`) to a healthy Garage node.

## API

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/api/products` | List products |
| `POST` | `/api/products` | Create a product with an optional image |
| `POST` | `/api/buy` | Reduce stock (row-locked transaction) |
| `GET` | `/api/image/<key>` | Return an image from Garage |
| `GET` | `/health/live` | Liveness: process is running |
| `GET` | `/health` | Readiness: database and Garage reachable |

Validation rejects empty names, negative prices or stock, and unsupported image types (only `.jpg`, `.jpeg`, `.png`, `.gif`, `.webp`). Uploaded files get a random UUID name. Stock changes use `SELECT ... FOR UPDATE`, which prevents overselling under concurrent purchases.

## Configuration

All settings come from environment variables in `/opt/shop-web/.env`:

| Variable | Purpose |
|---|---|
| `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASS` | PostgreSQL through the local HAProxy |
| `GARAGE_ENDPOINT` | `http://<haproxy>:3900` |
| `GARAGE_ACCESS_KEY`, `GARAGE_SECRET_KEY` | S3 credentials (from Ansible Vault) |
| `GARAGE_BUCKET` | `product-images` |
| `GARAGE_REGION` | `garage` |

> **Security note:** Credentials must never be committed to Git. The `.env` file is generated by Ansible with mode `0600`.

## Container image

```dockerfile
FROM python:3.12-alpine
RUN apk add --no-cache gcc musl-dev postgresql-dev
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 5000
CMD ["gunicorn", "--bind", "0.0.0.0:5000", "--workers", "2", "--timeout", "60", "app:app"]
```

Compilers are needed because `psycopg2` is built against the Alpine C library. Deployment and the Compose definition are described in [08_Docker.md](08_Docker.md).

## Health checks

```sh
curl -s http://127.0.0.1/health/live
curl -s http://127.0.0.1/health
```

`/health` returns `503` and a JSON body naming the failed check (`database` or `garage`). HAProxy uses this endpoint, so a failing site is automatically bypassed. See [10_Web_Server_NGINX.md](10_Web_Server_NGINX.md).

## Troubleshooting

| Symptom | Check |
|---|---|
| `database: failed` | `.env` host/password, HAProxy port 5000, Patroni primary |
| `garage: failed` | S3 key, bucket `product-images`, HAProxy port 3900 |
| Image upload fails | Backend log: `docker logs python-backend` |
| Container restarts | Missing or malformed `.env` |

## Result

The backend is a stateless service: all data lives in PostgreSQL and Garage, so any web worker can serve any request and a failed container can be replaced without data loss.
